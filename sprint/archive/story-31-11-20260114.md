## Story Info

### Description

Apply the same consolidation pattern from Story 31-10 to SM's bookkeeping subagents. Currently SM has 6 separate subagents:

- sm-finish-bookkeeping - Check PR, lint, Jira prep
- sm-finish-execution - Archive, Jira transition, cleanup
- sm-story-setup - Jira claim, branches, session write
- sm-work-research - Scan backlog, check Jira
- sm-file-summary - Read and summarize files
- sm-handoff - Handoff bookkeeping to TEA

These could be consolidated into fewer, more generic subagents:

1. **generic-sm-setup** - Combines story-setup + work-research
   - Scan backlog OR setup specific story based on params
   - Handles Jira operations (claim, status check)
   - Creates branches and session files

2. **generic-sm-finish** - Combines finish-bookkeeping + finish-execution
   - Pre-flight checks (PR, lint, Jira)
   - Archive and cleanup
   - Single subagent with phase parameter

3. **sm-handoff → generic-handoff** - Fold into existing generic-handoff
   - SM→TEA is just another phase transition (setup→red)
   - Gate type: manual (always passes after setup complete)
   - Unifies all handoffs under single subagent

4. Keep sm-file-summary separate (different concern - file reading)

5. **Remove deprecated handoff files from 31-10**
   - tea-handoff.md, dev-handoff.md
   - reviewer-handoff-approve.md, reviewer-handoff-reject.md
   - These were deprecated but not removed; now delete them

Benefits:
- Fewer subagent files to maintain (6 → 3, plus remove 4 deprecated)
- Consistent parameter patterns
- All handoffs unified under generic-handoff
- Easier to extend for new workflows
