## Acceptance Criteria
- [ ] Hooks reference .claude/pennyfarthing/scripts/ instead of /scripts/

- [ ] Existing functionality preserved (agent-session, check-context, etc.)

## Technical Context

### Problem
Currently Pennyfarthing creates a symlink at project root `/scripts/` → `.claude/pennyfarthing/scripts/`. This squats on a common directory name that end users should own for their own project scripts.

### Current State

**Symlink creation (init.ts:165):**
```typescript
{ target: '.claude/pennyfarthing/scripts', link: 'scripts' }
```

**Hook references (settings.local.json.template:31):**
```json
"command": "\"$CLAUDE_PROJECT_DIR\"/scripts/hooks/session-start.sh"
```

**run.sh script runner (lines 40-45):**
```bash
if [[ -f "$PROJECT_ROOT/scripts/$SCRIPT_NAME" ]]; then
    exec "$PROJECT_ROOT/scripts/$SCRIPT_NAME" "$@"
```

**Guides/docs reference:**
- `./scripts/run.sh agent-session.sh start sm`
- `eval $(./scripts/run.sh check-context.sh)`

### Solution

1. **Update settings template** - Change hooks to use full namespaced path:
   ```json
   "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/pennyfarthing/scripts/hooks/session-start.sh"
   ```

2. **Update run.sh** - Look in `.claude/pennyfarthing/scripts/` instead of `scripts/`:
   ```bash
   if [[ -f "$PROJECT_ROOT/.claude/pennyfarthing/scripts/$SCRIPT_NAME" ]]; then
   ```

3. **Remove symlink creation from init.ts** - Delete line 165

4. **Add migration to update.ts** - Remove legacy `/scripts` symlink if it points to `.claude/pennyfarthing/scripts`

5. **Update agent activation commands** - In slash commands that reference `./scripts/run.sh`, update to use the full path

6. **Update guides/docs** - Change all `./scripts/` references to `.claude/pennyfarthing/scripts/`

### Key Gotchas

1. **Backward compatibility:** Existing installs have the symlink - migration must be graceful
2. **Agent activation scripts:** Many use `./scripts/run.sh` pattern in markdown files
3. **User settings may have custom hook paths:** Template change won't affect existing installs
4. **run.sh is called from many places:** Ensure all lookup paths are updated

### Migration Strategy

1. **On update:** Check if `scripts/` is a symlink to `.claude/pennyfarthing/scripts/`
   - If yes: Remove it and log info message
   - If no (user's own scripts dir): Leave it alone
2. **Fresh installs:** Don't create the symlink at all
3. **Doctor command:** Already references correct paths (line 310, 374-375)

- Condition: Checks if path includes `.claude/pennyfarthing/scripts` or `pennyfarthing-dist/scripts`

**Pattern observed:** At `update.ts:202`, `readFileSync` is used where `readlinkSync` would be more appropriate for reading symlink targets. However, the EISDIR exception triggers the fallback to `realpathSync`, which handles it correctly. Code functions as intended.

**Error handling:**
- Directory symlink: EISDIR caught, handled by `realpathSync` fallback ✓
- Broken symlink: `realpathSync` throws, left for user (intentional per comment) ✓
- Regular directory: `isSymlink()` returns false, skipped ✓
- User's own symlink: Path check fails, left alone ✓

**Security:** No user input, filesystem operations only. No injection risk.

**Performance:** Single symlink check per update. Negligible overhead.
