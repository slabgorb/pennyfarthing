# Story 6-5: Add version tracking and compatibility warnings

## Story Details

| Field | Value |
|-------|-------|

| Epic | 6 - Interactive Theme Wizard |
| Points | 2 |

| Repos | pennyfarthing |

## Description

Warn users when custom themes may be outdated. Custom themes include `pennyfarthing_version` field, and agent-session.sh compares it with the current version, showing a warning on major/minor mismatch.

## Acceptance Criteria

- [ ] Custom themes include version metadata
- [ ] agent-session.sh detects version mismatch
- [ ] Warning displayed but doesn't block usage
- [ ] Warning only on major/minor mismatch (not patch)

## Technical Context

### Current State

1. **VERSION file**: Exists at project root with current version (3.7.1)

2. **theme-maker.md**: Already writes `pennyfarthing_version` field in skeleton (line 72), but hardcoded as "3.6.1" - should use actual current version

3. **agent-session.sh theme lookup** (lines 76-84):
   - Checks: `$PROJECT_ROOT/.claude/personas/themes/${theme}.yaml`
   - Checks: `$PROJECT_ROOT/personas/themes/${theme}.yaml`
   - MISSING: `$PROJECT_ROOT/.claude/pennyfarthing/themes/${theme}.yaml` (custom themes)

4. **Custom themes directory**: `.claude/pennyfarthing/themes/` - doesn't exist yet (created on first theme-maker use)

5. **Built-in themes**: No version metadata (e.g., the-expanse.yaml has no `pennyfarthing_version`)

### Implementation Requirements

1. **Update agent-session.sh**:
   - Add theme lookup for `.claude/pennyfarthing/themes/` (check FIRST for custom themes)
   - Create `check_theme_version()` function
   - Read `pennyfarthing_version` from theme YAML using yq
   - Compare with VERSION file content
   - Only warn on major/minor mismatch (X.Y differs), not patch (Z)
   - Warning format (from story description):
     ```
     Warning: Theme 'my-theme' was created with Pennyfarthing 3.2.0
              Current version: 3.5.3 - agent roles may have changed.
              Run '/theme-maker --update my-theme' to review.
     ```
   - Warning goes to stderr so it doesn't pollute persona output

2. **Update theme-maker.md**:
   - Read VERSION file instead of hardcoded version
   - Use `$(cat $PROJECT_ROOT/VERSION)` pattern or similar

3. **Version comparison logic**:
   - Parse semver: `MAJOR.MINOR.PATCH`
   - Compare MAJOR and MINOR only
   - Example: 3.2.0 vs 3.7.1 = MISMATCH (minor differs)
   - Example: 3.7.0 vs 3.7.5 = NO WARNING (only patch differs)

### Key Files

| File | Changes Needed |
|------|----------------|
| `pennyfarthing-dist/scripts/agent-session.sh` | Add version check function, update theme lookup order |
| `pennyfarthing-dist/commands/theme-maker.md` | Use dynamic VERSION instead of hardcoded |

### Test Scenarios

1. Built-in theme (no version) - no warning
2. Custom theme with matching version - no warning
3. Custom theme with different patch version - no warning
4. Custom theme with different minor version - WARNING
5. Custom theme with different major version - WARNING
6. Missing VERSION file - graceful fallback (no warning)
