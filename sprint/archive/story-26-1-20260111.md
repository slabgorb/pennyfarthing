# Story 26-1: Dogfooding & Installation Parity Audit

**Completed:** 2026-01-11
**Points:** 5
**Epic:** 26 - Dogfooding Audit & Installation Parity
**PR:** #183

## Summary

Comprehensive audit and fix ensuring Pennyfarthing's dogfood setup matches what users get from `pennyfarthing init`. Migrated from outdated chained symlink pattern to direct single-hop symlinks.

## What Changed

### Before (v4.0.0-v4.0.3 organic cruft)
```
.claude/pennyfarthing -> ../pennyfarthing-dist
.claude/agents -> pennyfarthing/agents  (2-hop chain)
.claude/commands -> pennyfarthing/commands  (single symlink)
.claude/skills -> pennyfarthing/skills  (single symlink)
```

### After (v4.0.4+ matches fresh init)
```
.claude/agents -> ../pennyfarthing-dist/agents  (direct, 1-hop)
.claude/commands/  (directory with 41 individual file symlinks)
.claude/skills/  (directory with 18 individual folder symlinks)
```

### Benefits
1. **Permission resolution** - Claude Code doesn't follow symlink chains; direct symlinks work
2. **Parity** - Dogfood structure now identical to fresh `pennyfarthing init`
3. **User extensibility** - Commands/skills directories allow adding user-specific files

## Files Modified

- `.claude/agents` - Direct symlink to `../pennyfarthing-dist/agents`
- `.claude/guides` - Direct symlink to `../pennyfarthing-dist/guides`
- `.claude/personas` - Direct symlink to `../pennyfarthing-dist/personas`
- `.claude/scripts` - Direct symlink to `../pennyfarthing-dist/scripts`

- `.claude/pennyfarthing` - Removed (no longer needed)
- `docs/DOGFOODING.md` - Updated to reflect v4.0.4+ structure

## Lessons Learned

1. **Organic cruft accumulates** - The chained symlink pattern was never intentional, it just grew that way
2. **Dogfood != fresh install** - When developing the framework, regularly test `pennyfarthing init` on a clean project
3. **Document the why** - DOGFOODING.md now includes historical context about pattern changes
