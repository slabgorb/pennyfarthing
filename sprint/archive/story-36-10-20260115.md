## Dev Session 2 - Race Condition Fix

### Root Cause Analysis

The intermittent enrichment was caused by **FIFO matching by tool name only**. When multiple Read/Edit tools were in flight simultaneously:

1. Message stream captures `tool_use` with `block.id`, `block.name`, `block.input`
2. OTEL `tool_result` events arrive in completion order (not submission order)
3. Old code matched FIFO by tool name → wrong tool got enrichment data

**Example:** Three parallel Reads for files A, B, C. If B completes first, it would get file A's enrichment because A was queued first.

### Fix Applied

**Enhanced `consumePendingToolInput()` to match on `file_path`:**

1. Parse `tool_parameters` from OTEL event (contains `file_path`)
2. Try precise match: `toolName + file_path`
3. Fall back to FIFO only if no file_path match found

This ensures Read(fileB) correlates with fileB's pending input, regardless of completion order.

### UI Enhancement

Changed enrichment display from language → filename:
- Before: `typescript 3.9KB 110 lines`
- After: `span-correlation.ts 3.9KB 110 lines`

User can infer language from extension; filename is more useful.
