## Technical Context

### Command Structure
Three new slash commands to enable quick commits without full ceremony:
- `/chore` - Creates `chore/*` branch, commits, merges to develop
- `/ux` - Creates `ux/*` branch for UI/styling tweaks
- `/doc` - Creates `docs/*` branch for documentation updates

All commands follow the same workflow pattern.

### Implementation Location
- Commands will be created in `pennyfarthing-dist/commands/`
- File naming: `chore.md`, `ux.md`, `doc.md`
- Each command is a standalone markdown file with implementation spec

### Workflow Per Command
1. Detect dirty files in working directory
2. Create appropriately-named branch from develop (branch naming: `chore/timestamp-slug`, `ux/timestamp-slug`, `docs/timestamp-slug`)
3. Stage all changes (or prompt for selective staging)
4. Generate commit message from file analysis
5. Commit with conventional commit format
6. Merge to develop (local)
7. Push develop
8. Log to sprint tracking under "chores" section

### Key Features
- **Auto-message generation**: Analyze changed files to create conventional commit message
  - Format: `chore: description` / `style: description` / `docs: description`
  - Example: `chore: add missing test utilities` or `docs: update installation guide`
- **Custom message override**: `/chore "custom message here"` to override auto-generation
- **Sprint tracking**: Log to `current-sprint.yaml` under new `chores:` section with entry format:
  ```yaml
  chores:
    - id: chore-001
      title: custom message or auto-generated
      date: 2026-01-12
      type: chore|ux|doc
      files: [list of changed files]
  ```
- **Multi-repo support**: Works with repos configured in `repos.yaml`
