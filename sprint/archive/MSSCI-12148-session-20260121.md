## Reviewer Assessment

**Decision:** CHANGES REQUESTED
**Reviewed by:** Argus Panoptes (Reviewer)
**Date:** 2026-01-21

### Issue: Architectural Overreach - WheelHub Not Required

The implementation uses WheelHub WebSocket connectivity (`connectToWheelHub`, `wsManager.onStats()`) to receive persona updates. This is **architectural overkill** for the portrait panel:

**Why WheelHub is wrong here:**
1. Persona data changes **infrequently** (only when agent switches)
2. Agent switches already update config files that sidebar watches
3. Adds unnecessary coupling to WheelHub server lifecycle
4. Complicates testing (requires WebSocketManager mocking)

**What should be used instead: File Watcher on config.local.yaml**
- Watch `.pennyfarthing/config.local.yaml` for theme changes
- This file is the single source of truth for current theme/persona

### Required Changes

1. **Remove WheelHub dependency:**
   - Delete `connectToWheelHub()` method
   - Remove `_statsUnsubscribe` field
   - Remove `WebSocketManager` import

2. **Add simple file watcher:**
   - Watch `.pennyfarthing/config.local.yaml` only
   - Parse YAML on change to get current theme
   - Use `vscode.workspace.createFileSystemWatcher()`

3. **Update extension.ts:**
   - Remove `agentPortraitWebviewProvider.connectToWheelHub()` call
   - Provider manages its own file watcher (like sidebar does)

4. **Update tests:**
   - Remove WebSocketManager-based tests
   - Add file watcher tests

### Files Requiring Changes
- `packages/vscode-extension/src/providers/agent-portrait-webview.ts`
- `packages/vscode-extension/src/extension.ts`
- `packages/vscode-extension/tests/MSSCI-12148-agent-portrait.test.ts`
