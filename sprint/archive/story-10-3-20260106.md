## Technical Context

### Pattern Definition
The fan-out/fan-in pattern enables:
- Spawning multiple agents/tasks in parallel
- Collecting results from independent work items
- Aggregating results for downstream processing
- Scaling workflow coordination across multiple repos

### Key Concepts
1. **Task Tool Parallelism** - Multiple Task calls execute concurrently
2. **run_in_background** - Enables true async execution
3. **TaskOutput** - Collects results from background tasks
4. **Result Aggregation** - Merging outputs into unified structure

### Documentation Structure

The guide should contain:
- **Problem Statement** - Sequential bottleneck, waiting for independent work
- **Solution Overview** - Parallel execution approach
- **State Diagram** - Mermaid and ASCII versions
- **Implementation Sections**:
  - Synchronous fan-out (multiple Task calls)
  - Asynchronous fan-out (run_in_background)
  - Fan-in with TaskOutput
  - Result aggregation patterns
- **When to Use** - Independent work items, multiple repos, data gathering
- **Error Recovery** - Partial failures, timeouts, fallback strategies
- **Anti-Patterns** - Dependent tasks in parallel, too many parallel tasks
- **Real Examples** - From Pennyfarthing codebase where parallelism could apply
