# Story 19-7: Create Telemetry Dashboard API

## Story Details
- **ID:** 19-7
- **Jira:** MSSCI-11432
- **Points:** 3
- **Priority:** P2
- **Epic:** 19 - Rich Agent Telemetry (claude_telemetry port)

## Acceptance Criteria
1. REST endpoints return structured JSON
2. Session stats include tokens, costs, duration
3. Tool breakdown shows frequency and timing
4. Agent stats enable performance comparison
5. Story costs enable budget tracking

## Technical Context

### Current State
Epic 19 has built a comprehensive telemetry infrastructure. All P1 stories (19-1 through 19-6) are complete:

| Story | Component | Purpose |
|-------|-----------|---------|
| 19-1 | otlp-receiver.ts | Parse OTEL events from Claude Code |
| 19-2 | telemetry-types.ts | TypeScript definitions (AgentSpan, ToolSpan, TokenUsage) |
| 19-3 | span-hierarchy.ts | Group events into parent/child span trees |
| 19-4 | agent-context.ts | Track tokens per agent (SM, TEA, Dev, Reviewer) |
| 19-5 | story-context.ts | Track tokens per story ID |
| 19-6 | tdd-metrics.ts | Track RED/GREEN/REVIEW phase durations |

The telemetry API exists at `packages/cyclist/src/api/telemetry.ts` with a single endpoint:
- `GET /api/telemetry/tdd` - Returns TDD phase metrics (already implemented)

### What Needs to Be Built
Four additional endpoints to complete the dashboard API:

| Endpoint | Data Source | Response |
|----------|-------------|----------|
| `GET /api/telemetry/session` | otlp-receiver, span-hierarchy | Session tokens, costs, duration |
| `GET /api/telemetry/tools` | span-hierarchy.getSpanHierarchy() | Tool frequency, timing breakdown |
| `GET /api/telemetry/agents` | agent-context.getTokenStatsByAgent() | Per-agent token stats |
| `GET /api/telemetry/stories` | story-context.getTokenStatsByStory() | Per-story cost attribution |

### Implementation Approach

Follow the existing pattern in telemetry.ts (lines 17-49):
```typescript
router.get('/endpoint', (req, res) => {
  const data = getDataSource();
  if (!data) {
    return res.status(404).json({ error: 'No data available' });
  }
  res.json(data);
});
```

**Data aggregation needed:**
- `/session`: Aggregate from span-hierarchy (total tokens, costs, session duration)
- `/tools`: Extract ToolSpan children, group by tool name, calculate frequency/timing
- `/agents`: Direct passthrough from getTokenStatsByAgent()
- `/stories`: Direct passthrough from getTokenStatsByStory()

## Reviewer Assessment

**PR:** #143
**Verdict:** REJECTED

**Code Review Evidence:**
- **Data flow traced:** `getSpanHierarchy()` from `span-hierarchy.ts:385` → spans iterated at `telemetry.ts:65` → token aggregation at `telemetry.ts:70-74` accesses `span.tokenUsage` which does NOT exist on `AgentSpan` interface
- **Pattern observed:** TypeScript interface mismatch - code accesses properties not defined on types
- **Error handling:** 404 responses are correctly implemented for empty states

**Critical Issues Found:**

| Severity | Issue | Location | Fix Required |
|----------|-------|----------|--------------|
| Critical | Property `tokenUsage` does not exist on type `AgentSpan` | `telemetry.ts:70-73` | Either add `tokenUsage?: { input: number; output: number; cache_read: number }` to `AgentSpan` in `telemetry-types.ts`, or read from `attributes['gen_ai.usage.input_tokens']` |
| Critical | Property `durationMs` does not exist on type `ToolSpan` | `telemetry.ts:132` | Use `child.endTime - child.startTime` or `child.attributes['tool.duration_ms']` |

**Build Verification:**
```bash

# Result: 5 TypeScript errors in packages/cyclist/src/api/telemetry.ts
```

**Root Cause:**
Tests pass because Vitest runs without strict type checking and test helpers create mock objects with these properties. But the TypeScript compiler correctly rejects the code because `AgentSpan` (defined at `telemetry-types.ts:114-144`) has no `tokenUsage` field, and `ToolSpan` (defined at `telemetry-types.ts:170-191`) has no `durationMs` field.
