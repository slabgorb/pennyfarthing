## Diagnosis

### Problem
The context meter in the stats strip shows "—%" because the IPC infrastructure is incomplete. The frontend has polling code ready, but the Electron main process doesn't expose the necessary IPC handlers or implement periodic polling.

### Existing Infrastructure
- `getContextUsage()` in api/context.ts - calls check-context.sh to get context percentages
- `/api/context` server endpoint - provides context data via HTTP
- Frontend polling code in stats-strip.js (lines 134-153) - ready to display context meter

### Missing Implementation
1. **IPC Handler:** No `context:get` handler in main.ts setupDataIPCHandlers()
2. **Preload API:** No `context.get()` method in preload.ts (only onUpdate listener exists)
3. **Polling Loop:** No periodic polling in startProjectWatchers()
4. **Broadcasting:** No context:update events when values change

### Reference Pattern
Token stats (toolStats:get) and tool stats work correctly in main.ts - use these as implementation template.

## Acceptance Criteria
1. `context:get` IPC handler registered in main.ts
2. `context.get()` method exposed in preload.ts
3. Polling interval calls getContextUsage() periodically (10-30s)
4. `context:update` broadcast when values change
5. Stats strip displays actual context percentage
6. Context meter updates in real-time during conversation

## Implementation Notes
- Follow existing pattern: main.ts handlers → preload.ts API → frontend listeners
- Polling interval: every 10-30 seconds (balance between responsiveness and overhead)
- Broadcast only on change to reduce event volume
- Reference files:
  - packages/cyclist/src/main.ts (for IPC handler patterns)
  - packages/cyclist/src/preload.ts (for ElectronContextAPI)
  - packages/cyclist/src/startProjectWatchers.ts (for polling loop)
  - packages/cyclist/src/stats-strip.js (frontend usage)
  - packages/cyclist/src/api/context.ts (getContextUsage implementation)
