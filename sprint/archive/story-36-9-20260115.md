### Problem Statement

The OTEL enrichment mechanism from Story 36-2 never runs because the guard at `otlp-receiver.ts:698` requires `event.spanId && event.traceId`, but Claude Code's OTEL logs don't include these fields at the logRecord level.

### Root Cause Analysis

**Investigation Round 1:** Added debug logging showing `spanId=undefined traceId=undefined` when OTEL events arrive.

**Investigation Round 2:** Inspected raw logRecord keys:
```
['timeUnixNano', 'observedTimeUnixNano', 'body', 'attributes', 'droppedAttributesCount']
```
There is NO `traceId` or `spanId` at the top level of the logRecord.

**OTEL Spec vs Reality:**
- OTEL spec says `traceId` and `spanId` should be top-level fields in LogRecord
- Claude Code simply doesn't include them in its OTEL logs export
- The code at lines 440-441 accesses `logRecord.traceId` and `logRecord.spanId` which don't exist

### Fix Required

1. **Remove the blocking guard** at line 698:
   ```typescript
   // BEFORE (broken):
   if (event.spanId && event.traceId) {

   // AFTER (always run for Read/Edit tools):
   // No guard needed - use pending tool input for correlation
   ```

2. **Use pending tool input's toolId as correlation key:**
   - Story 36-8 already captures `tool_use` from Claude message stream via `storePendingToolInput()`
   - The `pendingInput.toolId` can serve as the correlation key instead of OTEL spanId
   - Generate synthetic spanId from toolId if needed for the correlation map

3. **Update correlation logic:**
