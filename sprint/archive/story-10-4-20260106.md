## Technical Context

### Pattern Overview
Approval gates implement human-in-the-loop decision points in agent choreography. Key concepts:
- **Plan Mode**: Present proposed actions before execution
- **AskUserQuestion**: Prompt user for input/approval
- **Resumption**: Continue after approval received

### Reference Materials
- **TDD Flow Pattern**: See `guides/choreography-tdd-flow.md`
- **Helper Delegation**: See `guides/choreography-helper-delegation.md`
- **Fan-out/Fan-in**: See `guides/choreography-fan-out-fan-in.md`
- **Pennyfarthing Workflows**:
  - SM story setup (requests confirmation before claiming)
  - Reviewer phase (requests approval/rejection)
  - Session continuation (requests user approval to continue)

### Implementation Examples in Codebase

1. **Reviewer Approval Gates** (existing pattern)
   - Reviewer presents findings and asks for approve/reject
   - System pauses pending user response
   - Workflow continues based on approval

2. **SM Confirmation Points** (existing pattern)
   - Story setup requests final confirmation
   - Jira claim requires verification
   - Story completion requires approval before archiving

3. **Session Continuation** (documented in Epic 3)
   - Checkpoint saved before circuit break
   - User approval needed to resume
   - Session state restored from checkpoint
