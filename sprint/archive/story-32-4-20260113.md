## Technical Context

### Part of Epic 32: BMAD Artifact Compatibility

This story enables Pennyfarthing to load and integrate BMAD `project-context.md` files as shared agent context. Similar to how we load `CLAUDE.md` for Pennyfarthing-native guidance, this parser extracts technology stack and implementation rules from BMAD projects to inform our AI agents.

### Implementation Pattern

Follow the existing parsers in `packages/core/src/bmad/`:
- **story-parser.ts** - Parse individual BMAD story files (32-2)
- **epics-parser.ts** - Parse BMAD epics.md (32-3)

Your **context-reader.ts** will follow the same pattern:
1. Section-based markdown parsing (split on `## ` headers)
2. Extract and return structured types
3. Include comprehensive test coverage

### File Location

```
packages/core/src/bmad/context-reader.ts
```

### Format Reference

See `sprint/context/bmad-formats.md` section 4 (Project Context Format) for complete documentation including:
- Technology Stack structure (Frontend, Backend, Infrastructure)
- Critical Implementation Rules format
- Coding Standards, AI Agent Guidance sections
- Example real project context

## Acceptance Criteria

1. **Detects project-context.md in project**
   - Function checks for existence of `project-context.md` in project root or specified path
   - Returns null/empty result if file doesn't exist

2. **Parses technology stack section**
   - Extracts `## Technology Stack` section from markdown
   - Parses Frontend subsection (Framework, Language, State Management, Styling, Build Tool)
   - Parses Backend subsection (Language, Framework, Database, Cache, API Style)
   - Parses Infrastructure subsection (Cloud Provider, Container Runtime, Orchestration, CI/CD)
   - Returns structured object with optional fields for each technology category

3. **Extracts implementation rules**
   - Parses `## Critical Implementation Rules` section
   - Extracts numbered rules with descriptions
   - Returns as array of rule objects with `number`, `title`, and `description`
   - Handles multi-line rule descriptions

4. **Integrates with agent context loading**
   - Exported types match story-parser.ts pattern (interface + ParseResult)
   - Can be imported alongside other BMAD parsers in a context loader
   - Proper error handling for malformed markdown

5. **Works alongside our CLAUDE.md**
   - No conflicts with existing Pennyfarthing context loading
   - Returns structured types that can be merged with CLAUDE.md context
   - Document how BMAD context supplements (not overrides) CLAUDE.md

### Parsing Guidelines

1. Use same `extractSections()` pattern as story-parser.ts (split on `## `)
2. For Technology Stack: Parse nested `### ` headers for subsections
3. For Implementation Rules: Extract numbered list items (`1. **Title:** Description`)
4. Handle optional sections gracefully (return empty/null, not error)
5. Preserve markdown formatting in descriptions for agent reading
