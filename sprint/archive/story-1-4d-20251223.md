# Current Work Session

## Story 1-4d: Add Session File Locking

**Points:** 2 | **Priority:** P2 | **JIRA:** MSSCI-11127

### Technical Context

**Objective:** Add file locking mechanism to prevent concurrent session file conflicts when multiple agents/terminals access `.session` files.

### Files Requiring Locking Protection

| Priority | File | Risk Level |
|----------|------|------------|
| CRITICAL | `checkpoints.log` | Multi-agent concurrent writes |
| CRITICAL | `agent-logs.jsonl` | Continuous logging from all agents |
| HIGH | `session-log.txt` | Session start/stop events |
| HIGH | `current_work.md` | Worktree manager updates |
| MEDIUM | `current_work_wt_*.md` | Per-worktree session management |

### Implementation Approach

**New utility:** `scripts/utils/file-lock.sh`

Key functions:
- `lock_acquire <filepath> <lock_type> [timeout]` - Acquire lock (returns 0 on success, 1 on timeout)
- `lock_release <filepath>` - Release lock and cleanup
- `with_lock <filepath> <lock_type> <command>` - Execute command with lock held

**Lock mechanism:** BSD `flock` for macOS/Linux portability

**Lock types:**
- `exclusive` (write operations) - Only one holder
- `shared` (read operations) - Multiple holders allowed

**Timeout strategy:**
- Default: 10 seconds for critical files
- Stale lock detection: Remove locks older than 5 minutes

### Integration Points

| Utility | Changes Needed |
|---------|---------------|
| `checkpoint.sh` | Wrap `checkpoint_save()`, `checkpoint_rotate()` with exclusive locks |
| `logging.sh` | Wrap `_log()`, `log_rotate()` with exclusive locks |
| `session-start.sh` | Wrap session-log.txt append with exclusive lock |

### Acceptance Criteria

1. Lock mechanism prevents concurrent writes to session files
2. Graceful handling when lock cannot be acquired (timeout + error code)
3. Lock timeout and cleanup on stale locks
