## Technical Context

### Current State - Input Blocking

The TipTap editor in `packages/cyclist/src/public/js/editor.js` uses a simple `isSubmitting` flag (line 46) that **discards** messages when Claude is processing:

```javascript
// Line 793-796 - Current blocking logic
if (isSubmitting) {
  console.log('[Editor] Ignoring submit - already processing');
  return;  // MESSAGE IS LOST
}
```

### Architecture Overview

```
User types in TipTap editor (#editor)
        ↓
submitEditorContent() [editor.js:789]
        ↓
isSubmitting check [BLOCKS HERE]
        ↓
window.electronAPI.claude.send(markdown) [preload.ts:218]
        ↓
IPC → main.ts → ClaudeService.sendMessage()
        ↓
Stream responses via IPC 'claude:message'
        ↓
onComplete callback → resetSubmitting()
```

### Key Files

| File | Purpose |
|------|---------|

### Implementation Approach

1. **Add queue state in editor.js:**
   ```javascript
   let messageQueue = [];
   let isProcessing = false;  // rename isSubmitting
   ```

2. **Queue instead of discard:**
   ```javascript
   if (isProcessing) {
     messageQueue.push(markdown);
     updateQueueIndicator();
     return;
   }
   ```

3. **Process queue on completion in message-view-init.js:**
   ```javascript
   function processNextInQueue() {
     if (messageQueue.length > 0) {
       const next = messageQueue.shift();
       submitEditorContent(next);  // or direct send
     }
   }
   ```

4. **UI indicator:** Badge showing queue count near editor

5. **Persistence:** Save queue to localStorage, restore on load

6. **Clear option:** Button or keyboard shortcut to clear queue

### Edge Cases to Handle

- Queue during error state (retry vs discard?)
- Stop button behavior (clear queue or just current?)
- Session clear should clear queue
- Quick action buttons queue integration
- Max queue size limit
