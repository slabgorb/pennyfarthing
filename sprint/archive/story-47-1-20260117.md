## Technical Context

### Current State
- Epics in `sprint/current-sprint.yaml` have a `jira:` field that is manually populated
- `generic-sm-setup.md` handles story setup but has no epic creation logic
- `jira-sync.mjs` syncs existing epics but cannot create new ones
- `jira-lib.mjs` has no `createEpic()` function

### Implementation Approach

**Option A: Extend jira-lib.mjs** (Recommended)
1. Add `createEpicInJira(title, description, labels)` function to jira-lib.mjs
2. Add `ensureEpicExists(epic)` function that checks for jira field, creates if missing
3. Modify SM setup flow to call `ensureEpicExists()` before story setup

**Option B: New script**
1. Create `jira-create-epic.sh` / `jira-create-epic.mjs`
2. Call from SM setup when epic.jira is missing

### Files to Modify
| File | Change |
|------|--------|
| `pennyfarthing-dist/scripts/utils/jira/jira-lib.mjs` | Add createEpicInJira() function |
| `pennyfarthing-dist/scripts/utils/jira/jira-sync.mjs` | Add ensureEpicExists() or separate create mode |
| `.pennyfarthing/agents/generic-sm-setup.md` | Add epic jira check before story setup |

```bash
jira issue create --project MSSCI --type Epic \
  -s "Epic {N}: {title}" \
  -b "{description}" \
  -y Medium \
  -l pennyfarthing \
  --no-input
```

## Reviewer Assessment

**PR:** #315
**Verdict:** REJECTED

**Code Review Evidence:**

- **Data flow traced:** `epic.title` from sprint YAML → `ensureEpicHasJiraKey()` → `createEpicInJira({ title })` → template literal string → `execSync(cmd)` at `jira-epic-creation.ts:134` - **UNSAFE: command injection vulnerability**
- **Pattern observed:** Mock parameters (`_mockResponse`, `_mockError`) in production interfaces at `jira-epic-creation.ts:20-22` - unconventional but functional
- **Error handling:** YAML write at `jira-epic-creation.ts:284` has no atomic write protection - file corruption possible on partial write

**Security:** CRITICAL - Command injection at `jira-epic-creation.ts:133-134`. User-controlled `title` and `description` are interpolated directly into shell command string passed to `execSync()`. Malicious YAML input like `title: 'Test"; rm -rf / #'` executes arbitrary commands.

**Performance:** Acceptable - synchronous `execSync` is fine for CLI tool context.

**Issues Found:**

| Severity | Issue | Location | Fix Required |
|----------|-------|----------|--------------|
| Critical | Command injection via unsanitized title/description in shell command | `jira-epic-creation.ts:133-134` | Use `execFileSync` with array args OR escape shell metacharacters |
| Major | Non-atomic YAML file write risks corruption | `jira-epic-creation.ts:284` | Write to temp file, then rename |
| Minor | `extractEpicNumberFromJiraKey` doesn't trim whitespace before regex match | `jira-epic-creation.ts:231` | Add `.trim()` before matching |

**What Passed:**
