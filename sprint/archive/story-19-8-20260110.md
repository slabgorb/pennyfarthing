## Story Description

Forward enriched telemetry to external OTEL backends. Cyclist acts as a telemetry enrichment layer:
1. Receives raw Claude Code OTEL
2. Enriches with agent/story context
3. Exports to configured backend

Supported backends (via OTEL exporters):
- Grafana Cloud
- Honeycomb
- Datadog
- Any OTLP endpoint

Configuration via env vars (matching claude_telemetry pattern).

```
Claude Code (telemetry sender)
    ↓ HTTP POST
    ├─ /v1/metrics → parseOTLPMetrics → aggregateTokenStats

Query Layer:
    └─ telemetry.ts: REST API endpoints (/tdd, /session, /tools, /agents, /stories)

```

### Implementation Approach

1. **Create otel-exporter.ts** with:
   - `initExporter()` - reads env vars, validates endpoint
   - `exportSpans(spans: AgentSpan[])` - converts to OTLP format, sends HTTP POST
   - `exportTokenStats(stats: TokenStats)` - exports metrics
   - `setExportCallback()` - allows hooking into aggregation flow

2. **Hook into existing flow** in otlp-receiver.ts:
   - After `aggregateTokenStats()`, call exporter if configured
   - After `processLogEvents()`, export new spans

3. **OTLP HTTP Export format**:
   - POST to `/v1/traces` for spans
   - POST to `/v1/metrics` for token stats
   - Include auth headers from env var

4. **Error handling**:
   - Log export failures but don't block main flow
   - Retry with exponential backoff (optional)
   - Graceful degradation if endpoint unreachable

### OTLP Format Notes for Dev

The OTLP HTTP/JSON format requires:
- `resourceSpans[].resource.attributes[]` - service metadata
- `resourceSpans[].scopeSpans[].spans[]` - the actual span data
- Timestamps in nanoseconds as strings
- Span status codes: 0 (Unset), 1 (OK), 2 (Error)
- Trace IDs as hex strings (32 chars), Span IDs (16 chars)
