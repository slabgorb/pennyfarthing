## Technical Context

### Problem Statement

During a single TDD cycle, multiple subagents independently run the full test suite:
- `reviewer-preflight` runs tests (~36s)
- `dev-handoff` runs tests via quality gate (~36s)
- `reviewer-handoff-approve` could run tests (~36s)

Total waste: ~70-110 seconds per story.

### Solution Approach

Cache test results in the session file with timestamp. Subagents check cache before running tests:

1. **Session file gets new section:**
```markdown
## Test Cache
| Field | Value |
|-------|-------|
| Last Run | 2026-01-13T21:15:00Z |
| Git SHA | abc1234 |
| Result | GREEN |
| Pass | 78 |
| Fail | 0 |
| Duration | 36s |
```

2. **Cache validation logic:**
   - Check if cache exists
   - Check if git SHA matches current HEAD
   - Check if timestamp < 5 minutes old
   - If all pass → skip test run, use cached result

3. **Cache invalidation:**
   - Code changes (git SHA differs)
   - Cache too old (> 5 min)
   - Missing cache

## Story Summary

**Story 31-8: Eliminate Redundant Test Runs in Subagents**

### What Was Built

A test cache module that caches test results in session files to prevent redundant test runs across subagents during TDD workflow cycles.

**Core Module:** `packages/core/src/workflow/test-cache.ts`
- `parseTestCache()` - Parse cache from session file markdown table
- `validateTestCache()` - Validate cache freshness (git SHA + timestamp)
- `formatTestCache()` - Format cache entry as markdown
- `createTestCacheEntry()` - Create entry from test results
- `shouldSkipTests()` - Convenience function for subagents

**Integration Points Updated:**
- `testing-runner.md` - Writes cache after test runs
- `reviewer-preflight.md` - Checks cache before spawning tests
- `dev-handoff.md` - Checks cache in quality gate step

### Impact

- **Before:** 3 subagents each ran full test suite (~36s each = ~108s total)
- **After:** First subagent runs tests and caches; subsequent subagents skip if cache valid
- **Expected savings:** ~70 seconds per TDD cycle

### Acceptance Criteria Met

- [x] Test suite runs only once per TDD phase (cache enables skip)
- [x] Session file caches last test result with timestamp
- [x] Subagents check cache before running tests
- [x] Cache invalidated on code changes (git SHA comparison)
- [x] Infrastructure in place for time savings (measurement pending)

### Key Decisions

1. **Git SHA validation:** Cache invalidates immediately on any code change
2. **5-minute default TTL:** Configurable, prevents stale cache use
3. **Dual implementation:** TypeScript module + bash scripts (Haiku compatibility)
4. **Result states:** GREEN (pass), RED (fail), YELLOW (pass with skips)

### Learnings

- Haiku subagents run bash, not TypeScript - cache validation duplicated in markdown
- Cross-platform date parsing requires fallback (macOS vs Linux)
- Round-trip testing (format → parse) catches subtle formatting issues
