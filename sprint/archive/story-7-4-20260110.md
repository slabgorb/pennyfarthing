# Story 7-4: Aggregate Job-Fair Results into Benchmark Statistics

## Story Details
- **ID:** 7-4
- **Jira:** MSSCI-11389
- **Points:** 3
- **Priority:** P2
- **Epic:** 7 - Agent Performance Benchmarking Suite

## Acceptance Criteria
1. Job-fair results contribute to overall benchmark statistics
2. Baseline calculations incorporate job-fair control runs
3. Scenario performance tracked across themes

## Technical Context

### Current State
Job-fair runs generate valuable benchmark data stored in:
- `internal/results/job-fair/{theme}-{timestamp}/summary.yaml` - Individual runs
- `internal/results/job-fair/consolidated/{theme}/summary.yaml` - Consolidated per-theme
- `internal/results/baselines/{scenario}/{role}/summary.yaml` - Baseline data

Control runs exist in `consolidated/control/summary.yaml` with matrix data across roles.

### What Needs to Be Built
A new script `scripts/aggregate-benchmark-stats.js` (following 7-1 Node.js pattern) that:
1. Scans all consolidated job-fair results
2. Aggregates statistics per scenario across all themes
3. Incorporates control job-fair runs into baseline calculations
4. Generates `internal/results/aggregate-stats.yaml` with:
   - Overall scenario statistics (mean, std, n across all themes)
   - Theme rankings per role
   - Control vs persona comparisons
   - Efficiency metrics (if available)

### Implementation Approach
Follow patterns from story 7-1:
- Node.js with yq for YAML parsing (via execSync)
- Shell wrapper script for CLI compatibility
- Statistical calculations: mean, std_dev, min, max, n
- Output YAML format consistent with existing baseline/benchmark summaries

### Key Files to Reference
| File | Purpose |
|------|---------|
| `scripts/benchmark-runner.js` | Node.js + yq pattern from 7-1 |
| `internal/results/job-fair/consolidated/*/summary.yaml` | Input: consolidated theme results |
| `internal/results/baselines/*/summary.yaml` | Reference: baseline format |
| `scripts/job-fair-runner.sh` | Context: how job-fair data is generated |

### Acceptance Tests (TEA to implement)

2. Processes all consolidated job-fair directories
3. Outputs valid YAML with required sections
4. Calculates correct statistics (mean, std_dev verified)
5. Control runs incorporated into comparison data
