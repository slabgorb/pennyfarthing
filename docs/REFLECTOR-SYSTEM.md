> **Purpose:** Document the Reflector marker system for rationalization and refactoring.

## Executive Summary

The **Reflector** system is Pennyfarthing's protocol for signaling UI actions from Claude agent output to the visual terminal (Cyclist) and VS Code extension. It uses HTML comment markers that are parsed and converted to interactive UI elements.

## Marker Types

| Marker Type | Format | Purpose | UI Action |
|-------------|--------|---------|-----------|
| `HANDOFF` | `<!-- CYCLIST:HANDOFF:/agent -->` | Phase transition | Button: "Continue with {agent}" |
| `CONTEXT_CLEAR` | `<!-- CYCLIST:CONTEXT_CLEAR:/agent -->` | High context handoff | Clear session + reload agent |
| `INVOKE` | `<!-- CYCLIST:INVOKE:/agent -->` | Turbo mode auto-execute | Auto-submit agent command |
| `QUESTION` | `<!-- CYCLIST:QUESTION:yesno -->` | Binary decision | Yes/No buttons |
| `CHOICES` | `<!-- CYCLIST:CHOICES:1,2,3 -->` | Multiple options | Numbered choice buttons |

## TirePump: Context Clear System

**TirePump** is the context clearing subsystem - named for the bicycle metaphor of "inflating" a fresh context window.

### Decision Logic

```
                    TIREPUMP DECISION TREE

                    +----------------+
                    | Handoff Event  |
                    +-------+--------+
                            |
                            v
                  +--------------------+
                  | IS_CYCLIST == true?|
                  +---------+----------+
                      |            |
                     YES          NO
                      |            |
                      v            v
          +------------------+   +------------------+
          | permission_mode  |   | marker: ""       |
          | == "turbo"?      |   | (no marker)      |
          +--------+---------+   +------------------+
               |         |
              YES       NO
               |         |
               v         v
    +--------------+   +-------------------+
    | context      |   | marker:           |
    | > 60%?       |   | HANDOFF           |
    +------+-------+   +-------------------+
       |        |
      YES      NO
       |        |
       v        v
+-----------------+  +------------------+
| marker:         |  | marker:          |
| CONTEXT_CLEAR   |  | HANDOFF          |
| (TirePump)      |  |                  |
+-----------------+  +------------------+
```

### Context Calculation

Thresholds are configurable in `.pennyfarthing/config.local.yaml`:

```yaml
context_budget:
  imminent_threshold: 65
  warning_threshold: 60
  critical_threshold: 85
  max_tokens: 200000
```

TirePump activates when:
1. `permission_mode == "turbo"` (auto-handoff enabled)
2. `usable_percent > 60%` (tirepump_threshold)

## Handoff Protocol

### The AGENT_COMMAND Pattern

**Critical insight:** Subagent output is NOT visible to the UI. Only the parent agent's direct text output is parsed for markers.

```
                    HANDOFF PROTOCOL SEQUENCE

 PARENT AGENT (Opus)              HANDOFF SUBAGENT (Haiku)
       |                                    |
       |  1. Write assessment to session    |
       |     file FIRST                     |
       |                                    |
       |  2. Spawn subagent --------------->|
       |                                    |
       |                                    | 3. Run gate checks
       |                                    |    (tests_pass, etc.)
       |                                    |
       |                                    | 4. Update session file
       |                                    |    (Phase, History)
       |                                    |
       |                                    | 5. Run pf handoff marker
       |                                    |
       |<------ Return AGENT_COMMAND -------|
       |                                    |
       |  ---                               |
       |  AGENT_COMMAND:                    |
       |    marker: "<!-- CYCLIST:...-->"   |
       |    fallback: "Run `/pf-dev`..."    |
       |  ---                               |
       |                                    |
       |  6. Output marker VERBATIM         |
       |     in direct text output          |
       v                                    |
   +----------------------------------+     |
   | <!-- CYCLIST:HANDOFF:/pf-dev --> |     |
   |                                  |     |
   | Run `/pf-dev` to continue        |     |
   +----------------------------------+     |
```

### Gate Types for Handoff

| Gate | Transition | Condition | Blocks If |
|------|------------|-----------|-----------|
| `tests_fail` | TEA -> Dev | Tests must be RED | Tests are GREEN |
| `tests_pass` | Dev -> Reviewer | All quality checks pass | Tests failing, git dirty, no PR |
| `approval` | Reviewer -> SM/Dev | Verdict in assessment | No verdict found |
| `manual` | SM setup | None | Never blocks |

**Script:** `pennyfarthing-dist/scripts/core/check-context.sh`

- `CONTEXT_PERCENT` - Total context usage
- `CONTEXT_USABLE_PERCENT` - User conversation usage
- `IS_CYCLIST` - Running in Cyclist terminal
- `USE_TIREPUMP` - Should use CONTEXT_CLEAR marker

## Consistency Issues

### Current Problems

| Issue | Location | Impact |
|-------|----------|--------|
| Duplicate regex | `quick-actions.js:161`, `reflector.ts:32` | Maintenance burden |
| Different function names | `detectStructuredMarkers` vs `detectMarkers` | API confusion |
| Inline code stripping | Both files strip code blocks differently | Potential edge case bugs |
| Hardcoded threshold | `check-context.sh:137` has `tirepump_threshold = 60` | Not configurable |
| No shared types | `Marker` interface defined separately | Type drift risk |

### Proposed Refactoring

```
@pennyfarthing/shared (new or existing package)
  marker/
    types.ts          # Marker interface, MarkerType enum
    detect.ts         # detectMarkers() - single implementation
    strip.ts          # stripMarkers() - single implementation
    constants.ts      # MARKER_PATTERN regex, MARKER_TYPES
    index.ts          # Re-export all

packages/cyclist/
  -> import { detectMarkers, stripMarkers } from '@pennyfarthing/shared/marker'

packages/vscode-extension/
  -> import { detectMarkers, stripMarkers } from '@pennyfarthing/shared/marker'
```

### Benefits

1. **Single source of truth** for marker parsing logic
2. **Shared TypeScript types** prevent drift
3. **Easier testing** - test once, use everywhere
4. **Consistent behavior** across all consumers

## Summary

The Reflector system provides a reliable, extensible mechanism for agent-to-UI communication through HTML comment markers. TirePump extends this for autonomous operation by automatically clearing context and reloading agents when context pressure is high. The handoff protocol ensures subagent work is properly surfaced to the UI by requiring parent agents to output markers verbatim.

**Key principle:** Markers must appear in the parent agent's direct text output, not in tool results.
