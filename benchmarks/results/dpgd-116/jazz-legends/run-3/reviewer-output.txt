## Findings

### Blocking Issues

**1. [CRITICAL] Nightly `rustfmt` fails across 9 files — `cli.rs`, `client.rs`, `completion.rs`, `init.rs`, `query.rs`, `security.rs`, `siem_client.rs`**

Per gotchas.md: *"Always include `cargo +nightly fmt --all --check` in the preflight. Nightly rustfmt enforces import ordering that stable does not. If it fails, flag it before approval — don't let it slip to post-merge."*

Key issues: import ordering in `completion.rs` (std must come before external crates under nightly), long `#[command(after_help = ...)]` attributes need multi-line formatting in `cli.rs`, builder chains reformatted in test files. 12+ diffs total.

**Fix:** Run `cargo +nightly fmt --all`.

---

**2. [HIGH] `uuid_v4_simple()` generates non-UUID strings — `output.rs:136-141`**

```rust
fn uuid_v4_simple() -> String {
    format!("req-{}-{}", d.as_secs(), d.subsec_nanos())
}
```

This produces `"req-1741427200-123456789"`, not an RFC 4122 UUID. AC-4 specifies `ResponseMetadata` with `request_id`. The `uuid` crate is already a workspace dependency but not used here. This is a semantic bug — downstream consumers expecting UUID format will break. Tests only check field presence, not format validity.

**Fix:** Use `uuid::Uuid::new_v4().to_string()` or at minimum rename the function to not imply UUID.

---

**3. [HIGH] `chrono_now()` returns raw epoch seconds, not ISO 8601 — `output.rs:144-150`**

```rust
fn chrono_now() -> String {
    format!("{}Z", d.as_secs())
}
```

Produces `"1741427200Z"` instead of `"2025-03-08T12:00:00Z"`. The `timestamp` field in `ResponseMetadata` should be human-readable ISO 8601. `chrono` is a workspace dependency but unused.

**Fix:** Use `chrono::Utc::now().to_rfc3339()` or similar.

**6. [MEDIUM] `AXIATHON_TIMEOUT` env override silently ignores invalid values — `config.rs:59-62`**

```rust
if let Ok(secs) = timeout.parse::<u64>() {
    self.timeout_secs = Some(secs);
}
```

If a user sets `AXIATHON_TIMEOUT=banana`, it's silently ignored with no warning. An operator debugging connection issues could be misled. Consider logging a warning via `tracing::warn!` or returning an error.

---

**7. [MEDIUM] `NotFound` error doesn't sanitize URLs — `error.rs:60`**

```rust
Self::NotFound(msg) => write!(f, "not found: {msg}"),
```

`General`, `Unauthorized`, and `ServerError` all pass through `sanitize_message()`, but `NotFound` and `Config` display `msg` raw. If a 404 error message contains a URL with embedded credentials, it would be exposed. Should use `sanitize_message(msg)` for consistency.

---

**8. [LOW] `format_value` uses `unwrap_or` for JSON serialization — `output.rs:94-95`**

```rust
let data = serde_json::to_value(value).unwrap_or(serde_json::Value::Null);
```

If serialization fails, the user gets `null` with no indication of failure. This is silent data loss. Acceptable for a framework story but worth noting for future handlers that pass complex types.
