# Story 6.1 CLI Framework — Adversarial Code Review

## Findings

### HIGH (Blocks PR)

**[HIGH] H-1: `main.rs` is a non-functional placeholder — AC-3 unfulfilled for the binary** at `crates/axiathon-client/src/main.rs:5`

`main.rs` just prints "not yet implemented" and exits 1. It never calls `Cli::parse()`, never dispatches commands, never maps `CliError::exit_code()` to `std::process::exit()`. AC-3 explicitly requires: *"main.rs catches errors and calls std::process::exit()"*. The entire CLI framework exists as library code that the binary cannot use. Running `cargo run -p axiathon-client -- status` prints "axiathon CLI not yet implemented" regardless of arguments.

**[HIGH] H-2: `Commands` enum and `Cli.command` field are private — no dispatch possible** at `crates/axiathon-client/src/cli.rs:77`

`enum Commands` is `pub(crate)` (implicitly private to the crate since no `pub`) and `Cli.command` is a private field with no accessor. Even when `main.rs` is wired up, there is no way to dispatch commands. The `Cli` struct exposes getters for global flags but has zero mechanism to access the parsed `Commands` variant. Either `Commands` needs to be pub with a `command()` getter, or `Cli` needs a `pub fn dispatch(&self) -> Result<(), CliError>` method.

**[HIGH] H-3: `cargo +nightly fmt --all --check` fails — import ordering violations** across 14 files

Per `_bmad/reviewer-gotchas.md`: *"Always include cargo +nightly fmt --all --check in the preflight. If it fails, flag it before approval."* Nightly rustfmt wants `std`/`extern`/`crate` import grouping with blank lines between groups. Every `commands/*.rs` file, `cli.rs`, and `config.rs` have ordering violations.

### MEDIUM (Does not block, should fix)

**[MEDIUM] M-1: `init` command has no handler — AC says "functional, not stub"** at `crates/axiathon-client/src/commands/init.rs:1`

AC-9 scope says *"axiathon init first-time setup (functional, not stub)"*. But `init.rs` is just an empty `InitArgs` struct with no handler function at all — not even a stub like every other command has. Contrast with `completion.rs` which is genuinely functional.

**[MEDIUM] M-2: Config silently accepts unknown fields — `token` field ignored without warning** at `crates/axiathon-client/src/config.rs:11`

`RawConfig` uses serde's default deserialization which silently drops unknown fields. A config file containing `token = "my-secret"` parses without error, giving the user no feedback that their token is being ignored. The security test at `security_test.rs:155` passes because `config.token()` hardcodes `None`, but the *file* was accepted without complaint. Add `#[serde(deny_unknown_fields)]` to `RawConfig` so users get an explicit error if they put secrets in the config file instead of the keychain.

**[MEDIUM] M-3: `thiserror` is a declared dependency but never used** at `crates/axiathon-client/Cargo.toml:23`

`thiserror` is in `[dependencies]` but `error.rs` manually implements `Display` and `std::error::Error`. Per `rust.md`: *"Use thiserror for error enums."* Either use it or remove the dead dependency. Dead dependencies increase compile time and attack surface.

### LOW (Informational)

**[LOW] L-1: `OutputFormatter` is a struct, not a trait as specified** at `crates/axiathon-client/src/output.rs:39`

AC-4 and the architecture doc specify *"OutputFormatter trait with Table/Json/Csv implementations"*. The implementation uses a struct with a format enum discriminant. Functionally equivalent for now, but diverges from the specified design and may complicate future extensibility (e.g., custom formatters).

**[LOW] L-2: `SiemClient::get` doesn't validate path starts with `/`** at `crates/axiathon-client/src/client.rs:50`

`format!("{}{path}", self.base_url)` silently produces a malformed URL if `path` doesn't start with `/` (e.g., `"api/v1/status"` → `"https://example.comapi/v1/status"`). A debug_assert or validation would catch misuse early.
