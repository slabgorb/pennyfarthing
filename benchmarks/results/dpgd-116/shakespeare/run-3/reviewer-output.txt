# Story 6.1 — Adversarial Code Review

## Findings

### [HIGH] Missing `logout` and `tui` command groups — AC-1 violation at `cli.rs:46-67`

AC-1 explicitly requires: *"`axiathon --help` must show all command groups: `query`, `rules`, `alerts`, `ingest`, `config`, `status`, `tenant`, `login`/`logout`, `tui`, `completion`, `init`."*

The `Commands` enum has 10 variants but is missing `Logout` and `Tui`. Even as stubs, these must exist to satisfy the help output requirement. This is a specification gap that will cause AC-1 validation to fail.

### [HIGH] Nightly `rustfmt` check fails — 11 formatting diffs across 6 files

Per `gotchas.md`: *"Always include `cargo +nightly fmt --all --check` in the preflight. Nightly rustfmt enforces import ordering that stable does not."*

Affected files:
- `src/config.rs` — function signature wrapping, chained method alignment
- `src/main.rs` — import ordering (nightly sorts `axiathon_client` before `clap`)
- `tests/cli_structure_test.rs` — import ordering, line wrapping
- `tests/output_formatter_test.rs` — assert macro formatting
- `tests/security_test.rs` — chained method and assert formatting
- `tests/shell_completion_test.rs` — assert macro formatting

This will fail CI. Must be fixed before merge.

### [MEDIUM] Silent failure on CRLF injection in `SiemClient` — `client.rs:28-46`

`with_token()` and `with_tenant()` silently set the value to `None` when CRLF is detected, returning `self` without error. The caller has no indication the value was rejected. A malicious or buggy token source could silently produce an unauthenticated client.

Should return `Result<Self, CliError>` so callers know the value was rejected, or at minimum log a warning via `tracing::warn!`.

### [MEDIUM] JSON metadata missing `timestamp` field — `output.rs:65-71`

AC-4 specifies JSON includes `ResponseMetadata` with `request_id, timestamp, api_version`. The implementation includes `request_id` and `api_version` but **no `timestamp`**. This is a partial AC-4 implementation.

### [MEDIUM] `RawConfig` silently ignores unknown TOML fields — `config.rs:16-22`

Serde's default behavior accepts unknown fields silently. A user who types `api_rul = "..."` (typo for `api_url`) gets no feedback — defaults are used instead. Add `#[serde(deny_unknown_fields)]` to `RawConfig` to catch configuration mistakes early. The intentionally-ignored `token` field is already declared, so it would still parse.

### [MEDIUM] `init` command is a stub despite spec requiring functional — `commands/init.rs`

The story scope says *"axiathon init first-time setup (functional, not stub)"*, but `InitArgs` is an empty struct with zero initialization logic. Completion has a real `generate_completions()` function; init has nothing. This is an incomplete deliverable per the spec.

### [MEDIUM] `--tenant` accepts raw `String`, not validated `TenantId` — `cli.rs:37`

The `--tenant` flag is `Option<String>` but `axiathon-core` provides `TenantId` with validation (UUID format, max 128 chars). Per the Rust coding rules: *"Validated constructors at trust boundaries."* The CLI is a trust boundary — tenant IDs from user input should be validated before being passed to `SiemClient`.

### [LOW] `NotFound` Display leaks resource identifier — `error.rs:68`

```rust
CliError::NotFound(resource) => write!(f, "resource not found: {resource}"),
```

Unlike `ServerError` and `ConfigError` which sanitize their inner values in Display, `NotFound` passes `resource` through verbatim. If the resource string contains internal IDs or paths (e.g., from a 404 response body), it leaks to the user. Inconsistent with the CWE-209 mitigation on other variants.

### [LOW] `CliError` missing `#[non_exhaustive]` — `error.rs:10`

Per Rust coding rules: *"`#[non_exhaustive]` on enums that will grow."* `CliError` is `pub` and will clearly grow as stories 6.2-6.7 add new error conditions. While this is less critical for a binary crate, it's a stated pattern violation.

### [LOW] Unused test variable warning — `tests/output_formatter_test.rs:114`

```rust
let parsed: serde_json::Value = serde_json::from_str(&output).expect("valid JSON");
```

Variable `parsed` is unused (cargo reports this warning). The test parses JSON but then checks the raw string instead. Either use `parsed` for the assertion or remove it.

### [LOW] No command dispatch — all commands exit with "not yet implemented (Story 6.1)" — `main.rs:18`

The binary parses CLI args but discards them (`let _cli`), returning NotImplemented for every command — including `completion` which has a functional library implementation. While subsequent stories will add dispatch, the story spec marks completion as "functional, not stub." The library function works, but the binary doesn't invoke it.
