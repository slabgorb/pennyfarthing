## Review Findings: Story 6.1 — CLI Framework & Structure

### [CRITICAL] Nightly `rustfmt` check fails — `cli.rs` formatting violations
`cargo +nightly fmt --all --check` produces diffs in `crates/axiathon-client/src/cli.rs`. The long `#[command(after_help = ...)]` attributes need reformatting. Per `gotchas.md`, nightly fmt **must** pass before approval.

### [HIGH] Hardcoded fake UUID and timestamp in `output.rs:134-148`
`uuid_v4_string()` returns a static hex string `12345678-1234-4567-8901-234567890123` and `timestamp_now()` returns a hardcoded `"2026-03-08T00:00:00Z"`. This means **every** JSON response has the same `request_id` and `timestamp`. This is not "placeholder" behavior — AC-4 requires `ResponseMetadata` with `request_id` and `timestamp`. Every response being identical breaks auditability and is functionally wrong. Either use a real UUID crate (already in workspace deps) and `chrono::Utc::now()`, or document this is a known limitation and don't pretend to produce real metadata.

### [HIGH] `--server` flag documents `env: AXIATHON_SERVER` but no `env = "AXIATHON_SERVER"` on the clap arg — `cli.rs:28`
AC-5 says `--server` supports the `AXIATHON_SERVER` env var. The doc comment says `(env: AXIATHON_SERVER)` but the actual clap attribute lacks `env = "AXIATHON_SERVER"`. Clap won't read the env var. This is a silent behavior gap — operators will set the env var and it will be ignored.

### [HIGH] Workspace dependency hygiene violation — 6 crate-pinned dependencies not declared in `[workspace.dependencies]`

The `Completion` variant uses `shell: String` and then `completion.rs` manually matches on lowercase strings. If an unknown shell is passed, it silently returns an empty string instead of returning an error. This is a silent failure — the user gets no output and no error.
