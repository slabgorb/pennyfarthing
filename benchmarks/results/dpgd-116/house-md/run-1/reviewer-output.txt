The test creates `SiemClient::new("https://api.axiathon.local/")` then calls `build_url("/api/v1/status")`. `build_url` strips the trailing slash from the base URL, producing `https://api.axiathon.local/api/v1/status`. The test then asserts `!url.contains("//api")` — but `https://` contains `//` and the assertion message says "URL should not have double slashes" while the URL is actually **correct**. The test is a false-negative bug: it panics on valid output. The assertion pattern `//api` doesn't match (the `//` is in the scheme), so looking more carefully — actually the URL `https://api.axiathon.local/api/v1/status` does contain the substring `//api` within `local//api` — wait, no. The trailing slash is stripped, so it's `https://api.axiathon.local` + `/api/v1/status` = `https://api.axiathon.local/api/v1/status`. The substring `//api` only appears if... Ah, the `//` is in `https://api` — yes, `https://api` contains `//a` not `//api`. Let me re-read: `https://api.axiathon.local/api/v1/status` — searching for `//api`: positions are `https:` then `//api.axiathon...` — YES, `//api` matches at position 6 in the scheme! The test is broken because it's matching the `//` in the `https://` scheme. This is a **buggy test assertion**, not a code bug. But it means the test suite doesn't pass, which is a blocking issue.

### [HIGH] F3: Missing `logout` and `tui` commands — AC-1 violation at `src/cli.rs:51`

AC-1 explicitly requires: "`axiathon --help` must show all command groups: query, rules, alerts, ingest, config, status, tenant, **login/logout**, **tui**, completion, init." The `Commands` enum is missing both `Logout` and `Tui` variants. Two of the required command groups are absent.

### [HIGH] F4: `RawConfig` silently ignores unknown fields — config security at `src/config.rs:8`

`RawConfig` uses default serde deserialization, which silently ignores unknown fields. The tests at `config_loading.rs:137-174` verify that `token` and `api_key` fields don't get loaded, but the test is vacuous: it checks `has_token_from_file()` which is hardcoded to `false`. If someone puts `token = "secret"` in the TOML, serde silently drops it — no warning, no error. This is a false sense of security. The `#[serde(deny_unknown_fields)]` attribute should be used, or at minimum a warning should be emitted. As-is, operators get no feedback that their config file contains unrecognized (possibly security-sensitive) fields.

### [HIGH] F5: `apply_env_override` silently swallows invalid values at `src/config.rs:73`

When `AXIATHON_TIMEOUT` is set to an invalid value (e.g., `"0"`, `"-1"`, `"abc"`), the override is silently ignored. No warning, no error. An operator who sets `AXIATHON_TIMEOUT=0` will get the default 30s timeout with zero indication their override was rejected. This violates fail-loud principles. At minimum, log a warning via `tracing::warn!`.

### [MEDIUM] F9: `format_json` generates random `request_id` per call — untestable at `src/output.rs:75`

Every call to `format_json` generates a fresh `Uuid::new_v4()`, making JSON output non-deterministic. This makes it impossible to snapshot-test or diff JSON output. The `request_id` should be injected, not generated inside the formatter.
