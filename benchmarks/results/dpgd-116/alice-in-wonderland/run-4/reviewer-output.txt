### 8. [MEDIUM] `SiemClient` CRLF rejection is silent — `client.rs:29-31`

```rust

    return self;  // silently swallowed
}
```

Builder pattern silently ignores bad input. The caller has no way to know the tenant ID was rejected. Should return `Result` or log a warning via `tracing::warn!`.

### 9. [MEDIUM] CSV writer errors silently swallowed — `output.rs:82-87`

```rust
let _ = wtr.write_record(headers);
```

Three `let _ =` calls discarding write results. If CSV serialization fails, the output is silently truncated with no error.

### 10. [MEDIUM] `RawConfig` accepts unknown TOML fields without warning — `config.rs:10-14`

`#[derive(Deserialize)]` without `#[serde(deny_unknown_fields)]` means a typo like `servar_url` is silently ignored. Users will get defaults with no hint their config is wrong.

### 11. [LOW] `main.rs` doesn't load config or initialize SiemClient — `main.rs:9-16`

The main function is Parse → Dispatch → Exit. There's no config loading, no SiemClient construction, no tracing initialization. While stubs don't need these, the wiring skeleton should exist so subsequent stories have a pattern to follow. The story says *"tracing init"* in the `main.rs` file description.

### 12. [LOW] `OutputFormat` default should auto-detect TTY — AC-4

AC-4 says: *"Table default for TTY, JSON for piped output."* The code has `format: Option<OutputFormat>` but no TTY detection logic anywhere. `std::io::IsTerminal` is mentioned in the spec but not used.
