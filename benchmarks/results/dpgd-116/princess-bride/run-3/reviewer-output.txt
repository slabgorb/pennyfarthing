## Findings

### [HIGH] Nightly rustfmt import ordering fails — `cli.rs`, `completion.rs`

Per gotchas.md: "Always include `cargo +nightly fmt --all --check` in the preflight." Nightly enforces import group ordering (std → external → crate). Two files have misordered imports. This will fail CI.

**Files:** `cli.rs:1-6`, `completion.rs:1-4`

---

### [HIGH] `OutputFormatter` uses `.unwrap_or_default()` on 5 serialization paths — silent data loss

`output.rs:48,65,73,81,95` all use `.unwrap_or_default()` on serde/CSV operations. If serialization fails, the user gets an empty table/JSON/string with zero indication of error. The `.ok()` calls on CSV write at lines 78 and 90 compound this — write failures are silently swallowed.

Per rust.md: "No `unwrap()` in production code — use `?` or `expect()` with actionable message." While `.unwrap_or_default()` isn't `.unwrap()`, it violates the spirit: silent failure is worse than a panic.

**File:** `output.rs:48,65,73,78,81,90,95`

---

### [HIGH] TTY auto-detection not implemented — AC-4 violation

AC-4 states: "Table default for TTY, JSON for piped output." The guardrails specify: "Use `std::io::IsTerminal` (not deprecated `atty` crate)." There is zero `IsTerminal` usage anywhere. Output is always table format unless `--format` is explicitly passed. Piped scripts will get table garbage instead of JSON.

**File:** `main.rs` (no TTY detection), `cli.rs:17` (hardcoded `default_value = "table"`)

---

### [HIGH] Handlers cannot access global Cli context (format, server, tenant, quiet, verbose)

Every handler signature is `fn handle(args: &CommandArgs)`. The `run()` function in `main.rs:19-36` only passes command-specific args. No handler can access `cli.format`, `cli.server`, `cli.tenant`, `cli.quiet`, or `cli.verbose`. Story 6.2 will require a handler signature change. This is architectural debt baked into the foundation story.

**File:** `main.rs:19-36`

**File:** `client.rs:30`, `config.rs:42`

**File:** `client.rs:73-75`

## Verdict: **CHANGES_REQUESTED**

Three HIGH issues block approval:

1. **Nightly fmt fails** — CI will reject this. Quick fix.
2. **Silent data loss in OutputFormatter** — `.unwrap_or_default()` on serialization paths violates error handling principles. Return `Result` or use `expect()` with context.
3. **TTY auto-detection missing** — AC-4 explicitly requires it, story guardrails specify `std::io::IsTerminal`. This is a spec requirement, not a nice-to-have.

The fourth HIGH (handler signature not passing Cli context) is architectural debt that will compound in Story 6.2 but is arguably acceptable for a stub-only story. I'd accept it with a `// TODO(6.2): pass Cli context to handlers` comment in `main.rs`.

Fix the three blocking HIGHs and the nightly fmt, and the Dread Pirate Roberts will let this ship pass.
