## Findings

### [CRITICAL] Test failure: `completion_command_requires_shell_argument` — at `tests/completion_tests.rs:87`

The test asserts that `axiathon completion` (no shell arg) must fail, but the `Completion` variant in `cli.rs:106-110` defines `shell: Option<Shell>`, making the argument optional. The test expects `is_err()` but clap parses it as `Ok(Completion { shell: None })`. This is a **test-vs-implementation mismatch**. Either the shell arg should be required (remove `Option`), or the test is wrong. Per AC-9, the shell argument IS required for completion generation, and `main.rs:27-29` already handles `None` by returning a `CliError::ConfigError` — but that runtime check doesn't help the clap parse-level test. **The shell arg should not be `Option` — it should be required at the clap level.**

### [HIGH] Nightly `rustfmt` check fails — multiple files

Per `gotchas.md`: "Always include `cargo +nightly fmt --all --check` in the preflight. If it fails, flag it before approval." Formatting violations exist across `cli.rs`, `client.rs`, `config.rs`, `init.rs`, and most test files. This must be fixed before merge.

### [HIGH] Silent header injection failure — at `client.rs:44` and `client.rs:51`

When `HeaderValue::from_str()` fails (e.g., tenant ID or token contains invalid header characters including `\r\n`), the code silently skips the header with `if let Ok(val)`. This means:
1. A malformed tenant ID silently sends the request **without tenant scoping** — data from the wrong tenant could be returned.
2. A malformed token silently sends an **unauthenticated** request.

This is a security concern (CWE-113 adjacency). The code should return an error when header values are invalid, not silently degrade. The security test at `security_tests.rs:43-57` acknowledges this weakness with a comment "It's also acceptable to reject at construction time" — but neither path actually rejects. The test is vacuous.

### [HIGH] `ClientConfig` accepts unknown TOML fields silently — at `config.rs:11`

`ClientConfig` derives `Deserialize` without `#[serde(deny_unknown_fields)]`. A typo like `servr_url` or a config key from a future version will be silently ignored, and the default will be used. Operators will think they've configured something when they haven't. This is a common source of production misconfiguration.

### [MEDIUM] Workspace dependency version mismatch for `toml` — at `Cargo.toml:22`

The story spec says `toml` 0.9, but `Cargo.toml` uses `toml = "0.8"`. Also, `clap_complete`, `comfy-table`, `dirs`, `csv`, `keyring`, `reqwest`, and `toml` are declared directly in the crate's `Cargo.toml` instead of being declared in `[workspace.dependencies]` in the root `Cargo.toml` as specified by AC and the technical guardrails. This violates the workspace dependency management pattern.

### [MEDIUM] `OutputFormatter` uses `expect()` for CSV operations — at `output.rs:108-114`

Six `expect()` calls in CSV/JSON formatting. While writing to a `Vec<u8>` shouldn't fail in practice, the project rules say "No `unwrap()` in production code — use `?` or `expect()` with actionable message." The messages exist but are not actionable (they just say "must not fail"). If any of these panics, the CLI crashes without a clean error message. These should propagate `Result` instead.

### [MEDIUM] `apply_env_overrides_from` and `apply_cli_overrides` are identical — at `config.rs:55-92`

Both methods have exactly the same implementation. There's no semantic difference. This suggests a copy-paste that will diverge silently in the future. More importantly, the actual env var reading (calling `std::env::var("AXIATHON_API_URL")`) is never shown — the caller must know to read env vars and pass them in. This indirection could easily be wired wrong.

### [MEDIUM] `Logout` command maps to same handler as `Login` — at `main.rs:24`

`Commands::Logout => commands::login::handle()` calls the same stub as `Login`. While both are stubs, the logout behavior should eventually differ (clear keychain vs authenticate). Using the same handler means a future implementor might not notice that logout needs its own path. A separate `logout.rs` stub would be cleaner.

### [LOW] Compiler warnings in tests — at `completion_tests.rs` and `cli_structure_tests.rs`

Multiple `unused_imports` warnings for `clap::Parser` and `Commands`. With `-D warnings` in CI, these would fail if test compilation used the same lint settings.

### [LOW] `no_color` flag doesn't affect table styling — at `output.rs:66-79`

The test at `output_format_tests.rs:50-59` passes vacuously because comfy-table never adds ANSI codes.
