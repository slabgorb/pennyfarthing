# Adversarial Code Review — Story 6.1: CLI Framework & Structure

*"I don't hold with this modern fashion for approving things just because they compile. Let's see what's REALLY going on."* — Granny Weatherwax

Our Nanny Ogg ran the preflight. Tests pass, clippy clean. That means nothing. Here's what's actually wrong.

---

## Findings

### `[CRITICAL]` 1. `main.rs` is a dead end — no command dispatch, no exit codes, no error handling at `main.rs:7-9`

`main.rs` parses the CLI and *throws away the result*. There is no command dispatch. No `match cli.command { ... }`. No error printing to stderr. No `std::process::exit()`. This means:
- **AC-3 is unmet**: Exit codes 0/1/3/4 never happen. Every command exits 0.
- **AC-10 is unmet**: Stub commands don't print "not yet implemented (Story X.Y)" — they silently succeed.
- **AC-9 partially unmet**: `axiathon completion generate bash` parses but produces no output.
- **AC-7 partially unmet**: `SiemClient` exists but is never constructed or used.

The binary is a parser with no behavior. This is the most critical finding.

### `[HIGH]` 2. Missing `tui` and `logout` commands — AC-1 violation at `cli.rs:49-120`

AC-1 explicitly requires: "query, rules, alerts, ingest, config, status, tenant, **login/logout**, **tui**, completion, init". The `Commands` enum has no `Tui` variant and `LoginCommands` has no `Logout` variant. Two of the required command groups are missing entirely.

### `[HIGH]` 3. Nightly `cargo fmt` check fails at `tests/siem_client.rs:29-30,183-186`

Per `gotchas.md`: "Always include `cargo +nightly fmt --all --check` in the preflight. If it fails, flag it before approval." Two formatting violations in `siem_client.rs`. This is a documented blocking gate.

### `[HIGH]` 4. Workspace dependency declarations missing — convention violation at `Cargo.toml` (workspace root)

The Rust rules say: "Workspace-level dependency declarations in root `Cargo.toml`." The story explicitly says to add `reqwest`, `comfy-table`, `keyring`, `clap_complete`, `dirs`, `csv`, `toml` to `[workspace.dependencies]`. None were added. The crate's `Cargo.toml` pins these directly (`clap_complete = "4"`, `comfy-table = "7"`, etc.), bypassing workspace version management. When a second crate needs `reqwest`, versions will diverge.

### `[HIGH]` 5. `--server` flag missing `AXIATHON_SERVER` env var support — AC-5 violation at `cli.rs:30-31`

AC-5 states: "`--server` supports `AXIATHON_SERVER` env var." The `server` field has no `#[arg(env = "AXIATHON_SERVER")]` attribute. Operators relying on the env var for CI/CD will get no server URL.

### `[MEDIUM]` 6. `chrono_now()` produces Unix epoch seconds, not ISO-8601 at `output.rs:98-104`

The doc comment says "Simple ISO-8601 timestamp" but produces `"1741123456Z"`. ISO-8601 requires `"2025-03-04T12:30:00Z"` format. The `JsonResponse.timestamp` field in JSON output is misleading — consumers parsing it as ISO-8601 will fail.

### `[MEDIUM]` 7. `RawConfig` silently accepts unknown fields at `config.rs:16`

No `#[serde(deny_unknown_fields)]`. A typo like `api_rul = "..."` is silently ignored. Operators debugging config issues won't get feedback that their field name is wrong. The `token` field is intentionally accepted-but-ignored, which conflicts with deny_unknown_fields, but a custom deserializer or explicit allowlist would be better.

### `[MEDIUM]` 8. `AXIATHON_TIMEOUT` env var silently ignores parse failures at `config.rs:51-53`

If `AXIATHON_TIMEOUT=abc`, the `parse::<u64>()` fails silently and falls back to the file/default value. No warning logged. Operator thinks they set 60s timeout but gets 30s.

### `[MEDIUM]` 9. Raw `String` for tenant ID instead of `TenantId` newtype at `cli.rs:35`, `client.rs:10`

Rust rules require: "Newtypes for IDs: `TenantId(String)`". `axiathon-core` exports `TenantId`. The CLI `--tenant` flag and `SiemClient.tenant` both use raw `String`, losing type safety.

### `[MEDIUM]` 10. `siem_client_rejects_token_with_newlines` test is vacuous at `tests/siem_client.rs:230-234`

The test constructs a client with a newline-injected token, then does... nothing. No assertion on the sanitized value. Compare with the tenant test at line 221 which actually checks `!tenant.contains('\n')`. The token test just says "Should not panic during construction" — that's not testing sanitization.

### `[LOW]` 11. `toml` version is 0.8, story specifies 0.9 at `Cargo.toml:25`

Story says `toml` 0.9. Crate uses 0.8. `toml` 0.9 does not exist on crates.io (0.8 is latest), so the story spec is wrong, but this should be documented.

### `[LOW]` 12. `OutputFormatter` uses `expect()` (panic paths) in production code at `output.rs:75,83,88,91-93`

Five `expect()` calls in formatting code. While the messages are descriptive (per Rust rules), these are reachable panic paths. Writing to a `Vec<u8>` buffer can't really fail, but a `?`-based approach would be more defensive.

### `[LOW]` 13. Stub tests construct errors manually, don't test actual dispatch at `tests/stub_handlers.rs`

All stub tests manually construct `CliError::NotImplemented(...)` and verify its Display. They don't test that running `axiathon query run "test"` actually produces that error — which it doesn't, because main.rs has no dispatch. These tests verify the error type's API, not the application's behavior.

## Summary

| Severity | Count | Blocks? |
|----------|-------|---------|
| Critical | 1 | YES |
| High | 4 | YES |
| Medium | 5 | NO |
| Low | 3 | NO |

The core problem is finding #1: the binary doesn't DO anything. It parses CLI args and exits. No dispatch, no output, no exit codes. This means AC-3, AC-9, AC-10 are functionally unmet despite having "passing tests" — the tests verify library APIs but not the binary's behavior. 

Four High findings also block: missing commands (tui/logout), nightly fmt failure, workspace deps not declared, and missing env var wiring.

---

## Verdict: **CHANGES_REQUESTED**

The binary is structurally incomplete. `main.rs` needs command dispatch with error handling and `process::exit()`. The `tui` and `logout` commands need stubs. Nightly fmt needs fixing. Workspace dependencies need to be declared at root. `--server` needs its env var. Fix the Critical and High findings, then re-submit.
