## Delivery Findings

- **Gap** (non-blocking): Current `ApiResponse<T>` in axiathon-core has `meta: Option<ApiMeta>` with `total/limit/offset` fields, but AC requires `meta` to always be present with `request_id` (UUID), `timestamp` (ISO 8601), `trace_id` (string). Dev will need to either extend `ApiMeta` or create a separate response meta type for the server layer.
  Affects `crates/axiathon-core/src/types.rs` (ApiMeta struct needs request_id, timestamp, trace_id fields).
  *Found by TEA during test design.*

- **Gap** (non-blocking): AC says `errors` should be "always present array (empty on success)" but current `ApiResponse<T>` has `error: Option<ApiError>` (singular, optional). Dev needs to change this to `errors: Vec<ApiError>` to match the AC.
  Affects `crates/axiathon-core/src/types.rs` (ApiResponse.error field needs to become `errors: Vec<...>`).
  *Found by TEA during test design.*
