**2 unfixable test failures** — both panic in the test helper before reaching server code:
- `null_bytes_in_auth_header_returns_401` — `\0` in header value is rejected by the `http` crate's `HeaderValue` validator, causing `Request::builder()` to fail at `.expect("request builder")`
- `xss_in_query_params_is_not_reflected` — `<script>` chars in URI are rejected by the `http` crate's URI parser, same panic point

These are test-level issues: the `http` crate correctly rejects invalid HTTP before our server code ever runs. The security properties these tests intend to verify are inherently enforced by the HTTP layer.
