**1 Test Defect:** `response_headers_do_not_reflect_user_input` — the test constructs an `http::Request` with `\r\n` (CRLF) bytes in a header value. The `http` crate v1.4.0 correctly rejects this as `InvalidHeaderValue`, and the test's `.unwrap()` panics before our server code runs. The http crate already prevents CRLF header injection at the protocol level, which is the correct security behavior. This test needs the `\r\n` replaced with a non-CRLF injection attempt to be valid.
